# Open-Data Topic Recommendation

## 推荐题目

**《甲软件和信息技术服务企业税收风险管控案例——基于年报、公告与官方政策的多源公开信息分析》**

这是当前没有企业授权资料时的备用方向，不应包装成企业内部调查案例。正文应明确“公开信息研究边界”，风险结论最高到 `POTENTIAL_RISK` 或 `NEED_TAX_REVIEW`，除非另有可核验的企业证据。

## 为什么选软件和信息技术服务业

1. 属于 2026 规程列明的行业，和计算机专业的数据工程能力匹配。
2. 上市公司年报通常有收入分部、研发费用、合同负债、应收账款、政府补助、关联交易和所得税费用等披露栏目，适合构造可复算的公开信息勾稽。
3. 业务链可以围绕“合同/项目或订阅 -> 履约/验收 -> 收入确认 -> 开票与回款 -> 研发/外包成本 -> 税费披露”建模。
4. 相较直播电商、盲盒、医药、白酒、新能源汽车等已有较多公开标杆题目，软件方向有较好的差异化空间。

## 备选顺序

若能获得公开资料更完整的样本，可考虑交通运输/物流；若能取得采购、库存、生产、销售的连续披露，可考虑智能制造。最终样本必须通过数据可得性检查，不按题目先验编造风险。

## 公开资料研究方法

1. 从 `software_company_shortlist.csv` 选 3—5 家候选公司，下载至少 2 个年度的原始年报 PDF、审计报告和重要公告。
2. 记录每份文件的证券代码、公告日期、报告期间、URL、下载时间和 SHA256。
3. 抽取并核对利润表、资产负债表、现金流量表、研发费用、合同负债、应收账款、政府补助、关联交易、所得税费用及分部收入。
4. 只计算公开字段可以支持的指标；缺少申报表、发票、合同或资金流水时标记 `TODO_MISSING_DATA`。
5. 通过国家税务总局、财政部和中国政府网核验政策，按案例期间记录 `policy_id` 和有效性。
6. 对每个异常建立“公开数据字段 -> 公式 -> 结果 -> 可能解释 -> 需要补证”的证据链，不把异常直接写成违法。
7. 用竞争 red-team 检查“公开披露是否足以称为第一手资料”；若不满足，向指导老师/组委会确认参赛资格边界。
